JavaScript Object Copying

This script shows what happens when two names point to the same object, when we make a shallow copy, and when we make a deep copy.

Imagine objects are boxes. A variable is a name tag pointing to a box. Some copies make a new outside box but keep sharing a smaller box inside it.

The final picture

After all the script's changes, these names and boxes are connected like this. Arrows show what each name points to.

  • Original object and its names
  • Shallow copy
  • Deep copy
1

Make the first object

a points to a box with a status, a short string, and another box inside called details. 

let a = {
  status: "fail",
  s: "har",
  details: { reason: "timeout" }
};
2

b gets the same box

let b = a does not make a new object. Both names point to the same box. So changing b.status also changes what you see through a. 

let b = a;
b.status = "pass";
console.log(a); // status is "pass"; reason is still "timeout"
3

c gets a shallow copy

The spread { ...a } makes a new outside box. Changing its top-level status affects only c. But the nested details box is still shared. 

let c = { ...a };
c.status = "ok"; // a.status stays "pass"
c.details.reason = "network error"; // a.details.reason changes too
console.log(a); // status is "pass"; reason is "network error"
4

deepCopy gets its own boxes

structuredClone(a) copies the object and its nested details. Now changing either box inside deepCopy leaves a alone. 

let deepCopy = structuredClone(a);
deepCopy.status = "copied";
deepCopy.details.reason = "copied reason";

console.log(a);        // "pass", "network error"
console.log(deepCopy); // "copied", "copied reason"

The original stays at status "pass" and reason "network error". The deep copy has its own values.

The one thing to remember

b = a: two names, one same box.

{ ...a }: a new outside box, but nested boxes can still be shared.

structuredClone(a): a new box and new nested boxes, for values it can clone.
